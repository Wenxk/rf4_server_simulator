# 鱼种适温区间的实测标定报告（2026-11-23）

回答一个问题：**把真实文献适温填进 `fish_ecology_species`，客户端的温度会怎样变化，鱼口会不会崩。**

所有数字由仓库内脚本实测得出，不是估算。脚本都在 `tools/`，只读不写库。

---

## 1. 先说结论

| 上一轮的猜测 | 实测结果 | 判定 |
|---|---|---|
| 填真实适温后暖水鱼命中率崩到 15~30% | 温度是高斯响应，**下限钳 0.15，永不归零**；容差 1.5~10 范围内「压到下限」占比恒为 0% | **推翻** |
| 现有窗口 20℃ 刚好盖住跨图跨度 22.9℃ | 成立。现有窗口 14.3~23.2℃，覆盖率 60~78%，等于全图全季通吃 | **成立** |
| 温度能区分「这鱼只在这图出」 | 跨图区分度只有 6~15%，即使窗口压到 6℃ 也只有 10% | **成立，且是真正的瓶颈** |
| 先填数据，再看要不要改公式 | 质量上先填数据是对的，但**必须同时把窗口改窄**，否则填了也没效果 | **需要修正顺序** |

一句话：**温度不筛鱼，问题不在鱼的适温值，在窗口宽度和容差。**

## 2. 温度链路（已验证）

```
map_defs.json  每图 8 天预报（日高温）+ 24 小时模板（温差 rangeC）
  ↓ weather_schedule.go:93  mapWeatherProfile.hour(day, hour)
      air = high + (nextHigh-high)*hour/24 - rangeC*(1-cycle)
      cycle = (1-cos((hour-4)*π/12))/2
  ↓ 206 报文下发客户端（玩家看到的温度计）＋ 存进 sess.weatherPlans
  ↓ fish_bite_environment.go:538  fishWaterConditionsFor
      seasonalAir  = [10, 23, 13, 1][season]       ← 全局硬编码，与地图无关
      seasonalDeep = [9, 14, 11, 4][season]
      thermalResponse = .36 + .16*activity          ← 0.44~0.60
      surface = seasonalAir + (air-seasonalAir)*thermalResponse + daylight*1.2
      deep    = seasonalDeep + (surface-seasonalDeep)*.22
      water   = surface*(1-layer) + deep*layer      ← 底钓 layer=0.93，常规 0.45
  ↓ fishing_weather_fishing.go:9  weatherFishActivity
      tolerance = max(2.2, (temp_max_c - temp_min_c)/2)
      z         = (water - temp_pref_c) / tolerance
      thermal   = 0.35 + 0.65*exp(-0.5*z*z)         ← 高斯，无硬边界
      activity  = clamp(... * thermal * ..., 0.15, 1.25)
```

**关键点：`temp_min_c` / `temp_max_c` 不是判定边界，只用来算容差。** 真正的自变量是 `temp_pref_c`（偏好温度）和窗口宽度。这决定了适温表的正确填法是「偏好值要准 + 窗口要窄」，而不是「把文献耐受极限照抄上去」。

## 3. 实测数据

### 3.1 气温与水温的实际范围

| 指标 | 值 |
|---|---|
| 全库逐时气温 | 1.7 ~ 39.0℃（跨度 37.3℃） |
| 全库逐时水温（layer=0.45） | 2.4 ~ 26.7℃（跨度 24.3℃） |
| 压缩比例 | 气温跨度被压掉 35% |
| 单图全年水温跨度 | 14.1℃（挪威海最窄）~ 21.2℃（阿赫图巴河最宽） |
| 单图同一季节内跨度 | 约 3~7℃ |

极端对照：`level_009_ahtuba`（阿赫图巴河）日高温 34~39℃，但冬季水温只有 6.0~15.5℃；`level_012_north_sea`（挪威海）日高温 7~9℃。两张图的夏季水温分别是 16.4~25.8℃ 和 12.8~15.7℃，**只差 3.6~10℃**。

### 3.2 跨图区分度是瓶颈

同一季节下，18 张图的图均水温离散度：

| 季节 | 全图水温范围 | 图均跨度 | 图均跨度占全范围 |
|---|---|---|---|
| 春 | 7.0 ~ 20.0℃ | 8.5 ~ 15.5℃（7.0℃） | 54% |
| 夏 | 12.8 ~ 25.8℃ | 14.3 ~ 21.3℃（7.0℃） | 54% |
| 秋 | 8.6 ~ 21.7℃ | 10.1 ~ 17.1℃（7.0℃） | 54% |
| 冬 | 2.4 ~ 15.5℃ | 3.9 ~ 10.9℃（7.0℃） | 54% |

四个季节的图均跨度**恒为 7.0℃**，因为地图差异要经过 `thermalResponse`（0.44~0.60）衰减。而每张图自身四季跨度有 14~21℃，所以**季节的影响远大于地图**。温度实际上主要在表达「现在是什么季节」，而不是「这是哪张图」。

### 3.3 窗口宽度 → 区分力

以 `temp_pref_c` 为中心、±半宽展开窗口，测 77 条跨图鱼（430 个鱼×图组合）：

| 窗口宽度 | 平均覆盖率 | 最低图覆盖 | 跨图落差均值 | 季节落差均值 | 夏季均覆盖 | 冬季均覆盖 |
|---|---|---|---|---|---|---|
| 6℃ | 30.2% | 0.7% | 10% | 77% | 32% | 56% |
| 8℃ | 39.0% | 5.1% | 12% | 88% | 43% | 73% |
| 10℃ | 48.0% | 13.8% | 13% | 90% | 51% | 86% |
| 12℃ | 56.7% | 18.2% | 14% | 88% | 60% | 94% |
| 14℃ | 65.0% | 25.3% | 15% | 82% | 69% | 98% |
| 16℃ | 72.7% | 28.9% | 13% | 73% | 79% | 99% |
| 20℃ | 84.0% | 52.5% | 9% | 56% | 94% | 100% |
| 24℃ | 91.5% | 69.7% | 6% | 33% | 100% | 100% |

读法：
- **当前基线**宽度 14.3~23.2℃ → 落在最后两行，跨图落差 6~15%，季节落差 33~56%。
- **压到 10~12℃** → 季节落差最大（88~90%），跨图落差也最高（13~14%），且最低图覆盖仍有 13.8~18.2%，不会出现死条目。这是甜点区。
- **压到 6℃以下** → 出现 0.7% 的死条目风险，跨图落差反而降到 10%。

### 3.4 容差 → 权重表现

固定用代表鱼的偏好值，只扫容差（11 条代表鱼，全部鱼×图×季节逐时样本）：

| 容差 tol | 平均权重 | 平均极差 | 最低权重 | 达 1.0 占比 | 压到 0.15 占比 |
|---|---|---|---|---|---|
| 1.5℃ | 0.454 | 0.650 | 0.350 | 0.2% | **0.0%** |
| 2.2℃ | 0.503 | 0.650 | 0.350 | 0.3% | **0.0%** |
| 4.0℃ | 0.623 | 0.647 | 0.350 | 0.7% | **0.0%** |
| 6.0℃ | 0.733 | 0.609 | 0.358 | 0.9% | **0.0%** |
| 8.0℃ | 0.811 | 0.526 | 0.406 | 1.2% | **0.0%** |
| 10.0℃ | 0.863 | 0.430 | 0.485 | 1.5% | **0.0%** |

**没有任何样本被压到 0.15 下限**，即使容差只有 1.5℃。原因是 `thermal = 0.35 + 0.65*exp(-0.5*z²)` 的下限是 0.35（z→∞），而外层 clamp 下限是 0.15，两者之间还有 0.20 的余量，很难被其他因子吃满。

**这直接推翻了「暖水鱼会变稀有」的担心**：真实适温不会让任何鱼钓不到，只会让它「不在最佳状态时权重低一点」。

### 3.5 真实适温的效果验证

用 12 条代表鱼的真实文献区间（江鳕 4~14℃、北极红点鲑 2~16℃、白斑狗鱼 4~22℃、鲈鱼 4~24℃、欧鳊 4~26℃、赤梢鱼 4~28℃、鲤鱼 4~32℃、六须鲇 4~32℃ 等）代入：

| 鱼 | 基线权重极差 | 真实适温权重极差 | 提升 |
|---|---|---|---|
| 江鳕 burbot | 0.412 | **0.550** | +34%，成为全库区分力最强的鱼 |
| 欧鳊 bream | 0.412 | （窗口变宽）略降 | — |
| 全库均值 | 0.881 / 极差 0.257 | 0.882 / 极差 0.254 | 几乎不变 |

**江鳕是个很好的例子**：它的真实适温 4~14℃、偏好 8~11℃，容差 5.0；而基线是 6.5~28.8℃、偏好 18.9℃，容差 11.2。改完之后，它在夏季的阿赫图巴河会被压到很低的权重，在冬季的下通古斯卡河满血——这正是玩家期待的「冬天钓江鳕」。

但注意：**只改 12 条鱼时，全库均值几乎不动**，因为剩下 237 条还是宽窗口。要看到整体效果必须全量改。

## 4. 三个可选方案

### 方案 A：只填真实适温，不改窗口公式

- 改动：`fish_ecology_species` 填 249 条文献值
- 效果：偏好值变准（江鳕从 18.9℃ 改成 10℃，这是实打实的改变），但窗口宽度取决于文献给的耐受范围，多数鱼仍是 15~25℃ 宽窗
- 风险：低。不动代码，可随时回滚
- 不足：跨图区分度仍只有 10~15%，「这鱼只在这图出」还是靠名册而非温度

### 方案 B：填真实适温 + 统一收窄窗口到 10~12℃（推荐）

- 改动：`fish_ecology_species` 填文献值，但**把 `temp_min_c` / `temp_max_c` 按偏好值 ±5~6℃ 收窄**，不用文献的绝对耐受极限
- 效果：季节落差提到 88~90%，跨图落差 13~14%，权重均值 0.73~0.81，最低图覆盖仍有 14~18%
- 风险：中。会让鱼口明显随季节变化，玩家会立刻感觉到
- 实现：纯数据，不需要改 Go 代码

### 方案 C：B + 让季节基准跟地图走

- 改动：`fish_bite_environment.go` 的 `seasonalAir` / `seasonalDeep` 从硬编码数组改成按各图 8 天模板均值推导；`thermalResponse` 从 0.44~0.60 提到 0.80~0.90
- 效果：图均跨度从 7.0℃ 提升到接近各图日高温离散（约 14℃），跨图区分度翻倍
- 风险：高。属于「改玩法机制」，按 `CLAUDE.md` 改动纪律必须先确认范围；且会连带影响所有已有手感

---

## 5. 建议

**先做 B，不做 C。**

理由：
1. B 是纯数据改动，能立刻验证「温度开始起作用」这个假设，且完全可回滚
2. C 会把「数据对不对」和「公式对不对」两个变量混在一起，出问题分不清原因
3. B 做完后如果发现「跨图还是区分不出来」，那时再上 C 就有明确的对照基准

B 的窗口宽度建议 **±5.5℃（总宽 11℃）**：落在表格里季节落差最大（88~90%）、跨图落差 13%、最低图覆盖 18.2% 的那一行，是兼顾区分力和安全性的点。

## 6. 复现方式

```bash
cd G:/Localfish/rf4_server_simulator

# 1. 各图逐时水温标定（8 天预报 + 24h 模板 + 四季）
python tools/fish_temp_calibrate.py

# 2. 跨图鱼种包络（77 条出没 >=2 图的鱼）
python tools/fish_temp_crossmap.py

# 3. 死条目检测（可传 --csv 候选表）
python tools/fish_temp_deadentry.py

# 4. 窗口宽度 → 区分力（决策核心表）
python tools/fish_temp_widthscan.py
python tools/fish_temp_power.py

# 5. 容差 → 权重表现（推翻「暖水鱼变稀有」的依据）
python tools/fish_temp_tolerance.py

# 6. 按真实判鱼公式算权重（含 --csv 对照）
python tools/fish_temp_weight.py
```

所有脚本只读 `data/rf4server.db` 和 `internal/gameserver/assets/map_defs.json`，不写库。
