# 管理控制台

管理控制台直接内嵌在 `launcher` 中，通过统一控制中心 `http://127.0.0.1:9500` 的“管理后台”页签进入，不再监听独立的 `8080` 端口。admin 的 HTTP handler 挂载在 `/admin/`，前端 API 使用 `/admin/api/*`；内部 handler 仍保持 `/api/*` 路由，便于测试和独立调试。控制台使用 `config.yaml` 中的管理员凭据进行认证；登录成功后返回 JWT，供控制台和 API 使用。

该界面可以修改玩家数据、发放物品、调整经济配置以及管理会话。请仅在可信网络接口上开放。

## 玩家管理

- 按 UID 或名称搜索玩家。
- 手工预建玩家档案：填 UID（留空按现有最大号 +1）、昵称和初始等级/银币/金币。
- 编辑等级、经验、银币、金币和银行存款。
- 查看并修改背包和鱼护内容。
- 添加或移除鱼。
- 编辑各钓鱼技能分类的熟练度。
- 发放目录中的物品并移除已有物品。
- 将在线玩家踢下线或封禁玩家。

影响在线客户端的修改会通过 gameserver 命令队列下发。

**新建玩家等于「登记账号」**：本服没有密码，客户端的登录名就是账号。网关按 `login=` 参数
找同名档案（ASCII 大小写不敏感，取最小 UID），首次命中会把「登录名 → UID」写进 `kv`
（`login_uid:<小写名>`）持久绑定，之后改名也不影响登录。因此：

- 后台建好 `WenXS` → 客户端用 `WenXS` 登录即进入该档案；同一台机器可以用不同名字切换账号
- **没建过的名字不会自动建档**，网关回落到来源 IP 账号（本机固定 `gateway.userid_start`，
  局域网按来源 IP 递增），输错名字只会进本机老号，不会多出空档案
- 请求不带 `login`、只带 `token=` 时按 token 里的 UID 走（`local|…|uid|…` 第三段），
  保证二次登录不会把刚切好的账号打回去
- 昵称留空沿用 `player`、银币默认 5000，新手装备仍由主服在首登时按 `starter_items.json`
  发放（播种看「背包是否为空」，不受预建档案影响）；重复 UID 返回 409，不覆盖已有档案
- 密码留空、不做校验：能访问网关的机器都能用任意已登记的名字登录，仅适合本机或可信局域网

手竿与博洛尼亚、纺车竿与枪柄竿分别共享技能等级，每组只计算一份投入；学习或重置任一项会同步整组，各项熟练度门槛仍独立。历史节点按组内最高等级读取，不批量改写旧记录，也不调整等级赠点和已有额外点数。

## 商店

- 基础商店目录为只读数据。
- 按商店和物品设置的覆盖价格与库存会单独存储。
- 价格和库存可以恢复为基础目录中的值。
- 控制台、商店浏览和购买结算使用同一套目录解析逻辑。

解析顺序和覆盖范围详见 [shop_catalog.md](shop_catalog.md)。

## 钓鱼配置

- 选择水域并配置咬钩概率和时间。
- 启用或禁用鱼种，并设置相对权重。
- 从完整鱼池中添加鱼种。
- 将水域配置重置为静态默认值。
- 「地图区域」页签：在游戏纸地图上拖拽画区域（自动吸附 40m 网格，悬停显示
  与游戏 HUD 同口径的显示坐标），点已有区域编辑；选鱼默认列出本图名册
  （带基础权重），外来鱼种切「全库搜索」。挪威海显示海图与声呐区号网格，
  按区号建区暂未开放（数据层保留 `sea_zone` 字段，硬拒绝保存，见
  `internal/admin/fish_zones.go`）；无标定地图保留「手动输入」弹窗兜底。

后续的钓鱼抽取和咬钩计时会读取这些修改，无需重启服务器。

- 「鱼种名册」每行「生态」：编辑**该水域该鱼种**的习性覆盖（水层/水温/昼夜/季节/活跃度/
  是否出鱼），留空的字段继承全局档案。没有覆盖行时行为与改前完全一致；保存后 30 秒内生效。
  弹窗顶部会列出该鱼种**当前继承到的具体值**（水层区间、水温区间、活跃度、昼夜/季节解读、
  全局是否出鱼），各输入框的占位符也写成「继承 0.17」而不是只写「继承」——所以
  「全部留空」本身就是正确的初始状态，不需要逐项填；只有想让某图与全局不一致时才填字段。
- 生效的水域级差异目前来自**覆盖表**：区域固定名册（`fish_zone`）为空时，每张图用的是同一套
  鱼种，水域间的区别只能靠这张覆盖表做。注意水温由世界钟与天气统一推算（季节基准气温是
  全局常量，见 `fish_waterConditionsFor`），**不随地图变化**，因此在这里改水温窗口只对
  「该鱼种在这张图的活跃区间」生效、不会凭空造出地图间的水温差；真正立刻有手感的用法是
  「不出鱼」和「活跃度」。
- 「鱼种名册」的权重列分三块，别混：
  - **基础权重**：该鱼种的档位预设值（普通 100 / 稀有 30 / 超稀有 5），全天不变；
  - **当前权重**：基础权重 × 当前时段系数，会随游戏时刻变（夜行鱼夜里翻倍、白天衰减），
    右侧小字是该系数；改「覆盖权重」输入框时这一列会即时重算；
  - **覆盖权重**：手工为本图指定的绝对值，优先级最高。
  鱼种名下的小标签是昼夜掩码的四段（晨/昼/暮/夜）：实心=活跃、淡出=不活跃、蓝框=当前时段。
  表头一行写明现在几点、活跃倍率与非活跃倍率。
- 鱼种名下还有一行**稀有度**（只读）：`超稀有 · 档位权重 5`。档位是**鱼种固有属性**，
  取自静态表 `species_rarity`（253 种：普通 169 / 稀有 45 / 超稀有 39），与钓获量、
  与本服测试进度都无关。看「这条鱼该多常见」就参照档位权重，想改就填覆盖权重。
  这一页**不再**展示本图/全服渔获名次，也没有「重算稀有度」入口——按渔获量分档的口径
  已整体移除，理由见 `docs/gameplay.md` 的「稀有度是鱼种固有属性」。
- 「按稀有度重设权重」按钮（名册工具栏右侧）：影响**所有水域**，不只是当前这张图。弹窗先列出
  每档多少鱼、多少行、攻略原值均值多少，确认后三档数值立即写入并生效（不用重启）。
  「回滚到攻略原值」清空预设，各图回到攻略站原始渔获计数。已手工设过覆盖权重的鱼不受影响。
- 这一页**没有**「钓法倾向」入口：钓法族 × 水层档的乘子矩阵已于 2026-11-18 整体移除
  （它和几何水层匹配重复计分，且会让「饵已经到鱼的水层」仍被按钓法二次惩罚）。
  现在饵到不到位只由几何水层匹配决定，钓法差异交给饵料/拟饵规则，理由见
  `docs/gameplay.md` 的「钓法差异只走几何水层匹配」。
- 「鱼种名册」的「爱吃的饵」列按鱼种状态显示两种口径：
  - 开了**自动抽取**的鱼种，第一行就是「🎲 本期开口 3/47」+ 本期抽中的**具体饵名**
    （按型号折叠，如 `红蚯蚓（10/14/18）· 沉底煮饵`），后面跟下次换饵时刻；下面一行
    「候选池」是这条鱼的 `allow` 全集（自动抽取就是从这个池子里抽的），再往下才是官服
    占比与证据。名单由 `/api/fish/config` 的 `bait_pick` 现算（与判鱼同一份规则、同一个
    时间桶 + 轮次偏移），刷新页面即是最新一轮。三种异常也会写在格子里：型号不足配额
    （本期全开）、自动轮换总开关未开（抽签不生效）、未取到名单（刷新重试）。
  - 没开自动抽取的鱼种，按「规则 / 官服占比 / 证据」显示；选中的就是静态 allow，
    不再有手工轮换组。改鱼口权重时可顺手在这一列核对「玩家拿 A 饵不咬，到底是
    这期没抽中，还是规则里压根没写」。
- 「判鱼追踪」卡片（页面下方，只读）：列出最近的真实咬钩判定，展开可看候选鱼种逐层权重
  （名册→水层地板→区域→饵规则→分布→生态→钓点→窝料→饵效→抽签）与空轮空因。用于回答
  「为什么空军 / 为什么是这条鱼」；不采查鱼助手与区域估算。开关与保留条数在
  「游戏参数 → 玩法与钓组 → 判鱼追踪」。
- 「游戏参数 → 收益与通知 → 发鱼模式」：三选一（档位比例 / 鱼猎四阶段 / 两档制），
  选中哪种就显示哪组的权重设置。鱼猎四阶段是一张 4×4 表（日常 / 聚鱼 / 发窝 / 巨物发窝
  × 未达标 / 达标 / 奖杯 / 蓝冠），逐格填相对值即可，保存时每行自动归一到 100%；
  四档全 0 的行服务端回退默认值。海钓与路亚共用这张四阶段表，两档制模式下淡水改走两档表。
- 「游戏参数 → 玩法与钓组 → 昼夜权重」：两个参数——总开关 `fish_diel_weight_enabled`
  与「非活跃时段禁口」`fish_diel_inactive_block`（默认开）。昼夜形状本身是**四段曲线**
  （`fish_ecology.diel_curve`，峰值 1.0 / 最低 0.08，位序 `1` 夜 `2` 晨 `4` 昼 `8` 昏），
  不再是可调的「峰值倍率/非活跃倍率」——曲线低于 0.5 的时段整段禁口，权重归零；
  曲线本身就是数据，改手感请改曲线或逐鱼种覆盖权重。这一层**与「逐鱼种生态」总开关
  解耦、默认生效**：生态关着时它照样按鱼种昼夜掩码加权，因为「夜行鱼夜里更容易上钩」
  是玩家最能直接感知的一层。总开关设为 0 时判鱼与窝料门都回到中性。某鱼种算哪个时段活跃，
  看它生态档案的昼夜掩码，可在「鱼种名册」行的「生态」弹窗里逐水域改。

纸地图贴图来自客户端 `Data/maps` bundle（18 张 2048×2048）。官方客户端贴图
不入仓库（素材红线，同水层掩码口径）：用离线工具导出到部署包 `ref/paper_maps/`
（已在 .gitignore 的 `/ref/` 段内），后台按 `/maps/{贴图名}.webp` 运行时加载，
缺图时显示合成占位网格，工作台几何功能不受影响：

```text

```

期望贴图名单从 `internal/fishmaps/fishmaps.go` 解析（标定与贴图名的单一事实源），
客户端资源更新后重跑该命令即可；贴图目录缺失时无需重建，刷新页面即生效。

## 物品与鱼种图标

物品列表、鱼种列表和搜索弹窗会按需加载游戏图标。官方客户端素材同样不入仓库：
`tools/extract_item_icons.py` 从客户端导出到 `.gitignore` 覆盖的 `ref/`，再由
`tools/pack_item_icons.py` 生成单个 `ref/icons.zip`。发布装配脚本发现本地存在该包时会把
它复制进 Preview/Release 包；不存在时图标请求返回 404，前端 `onerror` 隐藏图片，
列表与所有管理功能保持可用。

```text
python tools/extract_item_icons.py --client-data '<客户端目录>/rf4_x64_Data'
python tools/pack_item_icons.py
```

导出与打包都只生成本地部署资源，不得提交客户端素材或含素材的截图。图标包在后台首次
请求时加载并按 Server 实例缓存；部署或替换 `ref/icons.zip` 后需重启管理服务。单个包
上限 128 MiB、最多 20000 个条目、单图上限 4 MiB；损坏包、路径穿越条目或超出限制时
按缺包降级。散文件仍可从 `ref/item_icons/`、`ref/fish_icons/` 直接读取，便于开发调试。

“新吃饵逻辑”是全水域开关，默认关闭。开启后按地图名册、后台启禁、已识别饵料和本地实钓搭配筛鱼；没有匹配鱼时不使用备用鱼池。明确不吃的饵优先排除，关闭后恢复旧判鱼流程。开关独立于调试预设保存，最多 30 秒影响后续判鱼，不重新抽取已咬钩的鱼；GM 指定下一条鱼仍保留原行为。

海图区号已接入：挪威海按抛竿落点所在水域定位区号，攻略里写“海图 NN 号区域”的鱼只在对应区号咬钩，“海图，区域不限”只要求当前在海图上；定位不到落点时保持中性。顺水漂流、`jig阶梯`、饵在水中运动按 `14/7` 钓组动画状态位判定，没有动作上报时不据此限制上鱼。船票与上船按 3/7 验票有效期加 `3/10` boat_use 实时上报判定：验票通过或收到上船上报视为在船上，收到下船上报立即判离船；没收到下船上报时租用到期才算已下船，本次会话没见过上船流程时保持中性。双饵沿用已有实现：多钩逐钩用各自的饵判鱼并保留组合加成。仍未接入的是内陆湖攻略网格坐标，控制台会显示这些范围。未识别且没有实钓证据的搭配暂不放行。规则随服务端发布，本次不自动联网更新统计数据。

规则表有两种落地方式：内置 `internal/gameserver/fishing_bait_rules.txt`（编译进二进制，全服统一、
改完要重编译）与后台「鱼种档案 → 饵料规则」的逐鱼覆盖（`fish_bait_override`，存库、15 秒内生效）。
覆盖表主键是 **`fish_key`**（2026-11-24 的 00083 迁移从中文名改过来）：中文名在库里既有 BOM 尾字符、
也有「大西洋鲑 / 大西洋鲑鱼」这类变体，还出现过同一条鱼两条覆盖互不相同的分叉。中文名现在只用于
展示与规则文本匹配，查表一律走 `fish_key`；只传中文名的旧接口由 store 层反查补齐。**覆盖是
整行替换**——保存时 `deny_json` / `bottom_json` / `condition` 留空，就会丢掉内置的禁饵、底钓只吃
与海图/jig 前置条件，鱼口立刻变宽或跑出限制水域。编辑框里的前置条件是**下拉**，选项就是规则表
原文（海图区号 / jig 阶梯 / 路亚上船运动 / 浮漂顺水漂流…），选完由服务端按同一套关键词解析；
「手竿或博洛尼亚竿」「浮漂立起」服务端没有对应上报，选了也不参与判定。全部可选值与逐条生效
范围见 `docs/parameter-dictionary.md` §4.1。**「吃 / 不吃 / 底钓只吃」支持整类加入**：
选择器顶部列出「全部（饵料 + 拟饵）」「饵料」「拟饵」以及 16 个天然饵类型、20 个拟饵类型
（颗粒、Pop-up 浮水饵、鱼片、蚯蚓类、Pilker 铁板…），点一下就把整类写进当前列表，标签显示为
紫色。整类词与具体饵名可以混用；写进规则的就是类型名本身（`颗粒`、`浮水饵`、`拟饵`），
内置规则表里的老写法（`蠕虫类`、`昆虫幼虫`、`鱼肉类`、`亮片类`…）继续有效。开了「自动抽取」
的鱼，整类词会展开成该类型的全部型号组，本期开口饵就从这一类里抽：allow 只写「颗粒」时，
池子 = 全部颗粒型号组（当前 98 款 / 30 组），每期在其中抽稀有度配额，抽中的型号连同
全部规格/颜色一起开口。

需要按外部证据批量补「爱吃饵」时用：

```text
python -I tools/fetch_rf4records.py --db data/rf4server.db --static server_data/static.sqlite3
python -I tools/merge_bait_allowlist.py --db data/rf4server.db --dry-run
python -I tools/merge_bait_allowlist.py --db data/rf4server.db --write
```

合并工具以内置规则为基线，只往 `allow` 追加，`deny`/`bottom`/`condition` 原样带过去；已被类目词
（蠕虫类/拟饵/各类饵…）覆盖、或会被本鱼「不吃」挡住的饵不会重复加入。默认口径：companion 只取
tier3，rf4 官服周纪录取占比 ≥5% 且样本 ≥5 的饵（`--min-share` / `--min-count` 可调）。
只给确有增量的鱼写覆盖，没有增量的鱼继续跟随内置表。

表格从 2026-11-24 起是六列（原九列，裁掉「偏好口（按类）」「饵效证据」「吃不吃」）：
鱼种 / 自动抽取 / 本期开口 / 规则（严格模式）/ 水域 / 水层。编辑弹窗只编辑静态 allow/deny，
不再有手工轮换组：

- **自动抽取**（第 2 列）：逐鱼开关，数据写 `fish_bait_auto_rotation`（按 `fish_key`）。
  勾上=该鱼参与按稀有度抽本期开口饵（普通 3 / 稀有 2 / 超稀有 1 个**型号**），抽中的型号
  连同它的全部规格/颜色一起成为本期 `allow`，没抽中的直接不在 allow 内（权重 0）。
  **名单里只点了一个尺寸也照整组开**（只写「甜奶油 PopUp 16」→ 12/16/20 一起开）。
  形态不合并：同为红虫味，活饵 / 沉底煮饵 / Pop-up / 颗粒 / 玉米分属不同组，折叠名一律带形态后缀
  （`玉米（8/14/18/24）· 颗粒`），否则「玉米」分不出是颗粒还是玉米粒。
- **本期开口**（第 3 列）：显示当期抽中的饵、配额/池子大小、下次切换时间。
- **规则（严格模式）**（第 4 列）：`allow`/`deny`/底钓只吃的折叠摘要，点行展开看全文。
- **水域**（第 5 列）：该鱼种出现的图，来自静态库 `loc_wiki_fish`，只读。
- **水层**（第 6 列）：活动区间与偏好位置的色带，点行展开看 ±0.15 容差带与钩容量适配。

被删的三列原先是纯展示，不写回任何链路：**偏好口**来自 `fish_ecology.diet_json`，唯一运行时
用途是咬钩节奏打分，而 `bite_pace_enabled`（饵效控速总开关，默认 0）是关的；**吃不吃**是
`applyBiteVerdict` 现算的一句话结论；**饵效证据**（`companion_bait_fish.tier`）确实仍在护鱼网
E 值（`fish_hunt.go:611`，tier3→1.0 / 2→0.75 / 1→0.5 / 无→0.35，`E<0.45` 落最慢档）与鱼体重
档位（`fishing.go:1581`，tier≥2 时 `mode = 1 + 0.12*tier*bait_pref_weight_shift`，tier3 即 1.36×）
生效——但那两处是运行时自带逻辑、后台不需要维护，所以**只移除列，计算保持不变**。

抽签是按时间桶算的（`hash(fish_key, floor(now/周期))`），所以到了一个周期才会自然换一批。
想立刻换一批调手感时点表格上方的「**↻ 立即重抽本期**」：它把轮次偏移 `bait_rotation_auto_round`
+1，所有开了自动抽取的鱼当场重抽，**周期长度和下次自然切换时刻都不变**（不会因为点一次按钮
把下一轮推后）。偏移落库、重启不丢；后台表格与游戏内读同一个值，不会出现表是新的一轮、
游戏里还是旧的一轮。要按外部证据批量重铺规则时别用它——那只改抽签，不动 `allow`。

开启顺序是先在「游戏参数 → 自动轮换」打开总开关（默认 7200 秒），再逐鱼勾选——只勾鱼不开
总开关不会生效。型号组数不超过配额的鱼自动全开（列里显示「型号只有 n 种，不足配额」）。

**自动抽取是唯一的动态 allow 来源**：手工轮换组（`groups_json` / `rotate_sec` / `rotate_mode`）
已在 2026-11-21 删除。覆盖表主键是 `fish_key`、整行替换内置规则；自动抽取的逐鱼开关单独放在
`fish_bait_auto_rotation`，给一条没有覆盖的鱼打开时不需要先复制内置 252 条规则，因此不会
让该鱼脱钩内置规则表的更新。

同页还有「规则外实证饵系数」（`bait_evidence_low_scale`，默认 0.1）：只对**没有 allow 规则**
的鱼生效，companion tier1~2 的饵按这个系数兜底。有 allow 的鱼名单外直接 0，不再看这个值。

两个必须守住的细节：**`allow` 里写的是规则词、不是某个 item**，整类词（`颗粒`、`浮水饵`、`拟饵`）
会展开成该类全部型号组；**重跑前按 `updated_by='bulk-A+B'` 清旧行**，工具已内置，手工保存过的行
不会被误删。

## 鱼种档案 · 经济四档

（第 3 个标签页；列表 → 编辑 → 试算 → 保存，POST 只带 `(fish_key, 四档)`。）

按鱼种调整经验速率与鱼市基准价，保存后立即通知主服刷新（最迟 30 秒）。列表同时给出四档
内置值与覆盖值，被覆盖的单元格高亮，状态列标记「已覆盖」；「只看已覆盖」可筛出改过的鱼种。

- **经验**单位是 XP/克，结算按 `trunc(速率 × 克重)`；四档统一阶梯 **1 : 3.265 : 20.40 : 40.81**
  （相对未达标，`fishXPGradeFactor`），每种鱼只有「未达标基数」是独立数据。覆盖值直接替换
  `fishXPRateFor` 的结果，不影响熟练度、加成与升级曲线。
- **鱼价**单位是「银/公斤（基准水域阿赫图巴）」，四档统一阶梯 **1 : 1.5 : 3 : 6**
  （`speciesPriceGradeFactor`），价表只存未达标基准价。其他水域仍按 `map_market_multipliers.json`
  的倍率折算，报价时再叠当日系数（±5%）与新鲜度，所以这里填的是基准价而不是某张图的成交价。
- **这两条阶梯是游戏内经验与鱼价结算的基准（2026-11-23 定稿，不再补实测样本）**。
  调整档位溢价只能改 `fishXPGradeFactor` / `speciesPriceGradeFactor` 并同步
  `TestUnifiedGradeLadder`，同时更新 `specs/changes/unified-grade-ladder`；
  不要用逐鱼种覆盖来做全局调价，否则 253 种里漏掉的会静默偏离基准。
- **留空＝跟随内置表**；只填一列也可以，另一列继续用默认。四档都空等于没有覆盖。
- **全部恢复默认**删除该鱼种的全部覆盖行，回到编译进服务的内置表，不需要改代码。
- 弹窗内可试算：给重量、档位与水域，当场显示经验与卖价；未保存的输入也能试算，不写库。
  试算结果会摊开算式 `基准价 × 水域倍率 × 当日行情 × 克重/1000 × 新鲜度`，
  并显示当日行情系数（0.95–1.05，按「UTC 日期 + 鱼种」哈希，同一鱼种当天固定、跨天会变）。
  **这是「1kg 卖价不等于每公斤价」的唯一原因**，不是算错——早期界面只显示
  「按刚钓获的新鲜度」，把行情系数隐掉了，2026-11-23 因此被报为 bug。

覆盖写 `species_econ` 表（`(fish_key, grade)` 一行，两列均可空）；保存与恢复都写审计并投递
`reload_tunables`。改价不重算已入护的鱼，只影响之后的询价与成交；重启主服后按库里的覆盖重新加载。

## 鱼种档案 · 生态基线

（「鱼种档案」页的第 1 个标签页；另外三个是饵料规则 / 经济四档 / 权重档位，见上节表格。）

按**物种**维护全套生态基线：水温区间、栖息水层、季节/昼夜掩码与曲线、活跃度、攻击性、
水流/光照/清澈度偏好，以及食性、天气、拟饵动作、底质、水色五个 JSON 矩阵。保存后投递
`reload_fish_ecology`，最迟 30 秒生效。

判鱼侧读生态档案是**三层合并**，本页改的是中间那一层：

```text
资产基线 fish_ecology         ← assets/fish_ecology_defs.json 按 profile_version 重灌
  ↓ 只改有值的字段
鱼种覆盖 fish_ecology_species ← 本页：物种本身的习性，全水域生效
  ↓ 只改有值的字段
水域覆盖 fish_ecology_loc     ← 「钓场与鱼口」页的生态覆盖弹窗：只影响一张图
```

- **列表金色＝已覆盖，灰色＝资产基线**；「只看已覆盖」筛出改过的鱼种，「只看到冷水鱼 /
  暖水鱼」按生效的偏好温度筛（≤12℃ / ≥22℃）。
- **留空＝继承基线**，只填关心的字段即可。决定判鱼的是 `fishEcologyFor`，后端不另算
  一份展示用的生效值——列表里 base + override 的合并由前端现算，避免两套逻辑走偏。
- **窗宽是温度能不能筛鱼的关键**。判鱼的热响应容差是 `max(2.2, (上限-下限)/2)`，窗宽
  20℃ 时高斯曲线极平，温度几乎不参与筛选。当前 253 种的中位窗宽是 20.2℃。编辑弹窗在
  温度三个输入框下方**实时显示窗口宽、热响应容差与窄/中/宽判定**，宽窗口标红。
- **季节掩码** 1春 2夏 4秋 8冬、**昼夜掩码** 1夜 2晨 4昼8昏，都是 0~15 的位掩码；弹窗用
  勾选框维护，不让人手算位运算。昼夜曲线填了就以曲线为准，掩码只在没有曲线时生效。
- **恢复基线**删除该鱼种的整条覆盖行，不影响其他水域（水域覆盖是另一张表）。
- **批量导入文献值**走 `ReplaceFishEcologySpeciesCurated`：它只替换 `origin<>'manual'`
  的行，后台手填的行原样保留，所以可以反复导入而不会冲掉人工校对结果。导入行在状态列
  显示为「文献值」。

覆盖写 `fish_ecology_species` 表（迁移 00082，一行一个鱼种，20 个可写列全部可空）。为什么不
直接改 `fish_ecology`：那张表由资产 JSON 按 `profile_version` 重灌，手工值会被版本升级冲掉。

## 天气预览

「天气预览」页把每张图的温度区间与逐小时天气摊开，效果贴近游戏内的天气预报：
7 张日卡片（图标 + 天气名 + 高低温 + 水温跨度 + 降雨小时数）、选中日的 24 小时温度曲线
（气温 / 表层 / 中层 / 底层四条线 + 降水雷暴柱 + 昼夜段底色）、温度分档条、四季对比，
以及全部水域的温度区间对比表。

**数据不另算一份**：页面只调 `/api/weather/preview`，后端直接调 `gameserver` 的
`WeatherPreviewForMap`，走的是 `mapWeatherProfile.hour` —— 与客户端下发的预报、判鱼用的
天气完全相同。后台看到的数字就是玩家客户端收到的数字。

几个口径必须记住：

- **即时天气类型复用判鱼同一套分类**（`fishingWeatherHour.kind()`）：雷暴 > 0.01 → 雷雨，
  降雨 > 0.5 → 大雨，降雨 > 0.01 → 小雨，云量 > 0.3 → 多云，云量 > 0.1 → 少云，否则晴。
  日卡片上的类型取 `forecast` 节点原值（客户端预报卡显示的就是这个），不是「正午那小时」。
- **温度区间的采样水层是 5 层**：0（表层）/ .2 / .45（默认钓组）/ .7 / .93（底钓），
  与判鱼侧 `layer` 随钓法变化的范围一致。只看中层会把区间算窄 2~7℃——2026-11-23 的鱼种
  适温标定就因为只算 0.45 而误判了 11 张图「温度不够」。
- **四季区间**扫该图 8 天预报模板 × 24 小时 × 5 水层，取各季代表日（1/16、3/16、6/16、9/16）
  换算水温。这是「这张图全年能出什么温度」；而页面顶部的区间只反映当前 7 天窗口。
- **游戏时钟按真实分钟走**：1 游戏小时 = 150 真实秒，所以小时内还有 40 个单位可算，
  不是永远停在 `:00`。
- 一次最多预览 14 天（`WeatherPreviewMaxDays`）。不传 `map` 的概览请求只返回每图的
  温度区间，`hours` 会被清空——18 张图 × 168 条逐时明细会让首屏 payload 涨到 3000+ 条。
- **日号只有一个口径：世界时钟轴**（2026-11-24 统一）：
  - 面板上「游戏内第 N 天」与客户端屏幕上的「游戏中 N 天」是**同一个数**，
    都等于 `floor((now − 2015-08-01) / 3600)`，从 0 起算、不 +1（`worldclock.DayAndHour`）。
  - 客户端那个数字是绝对时间轴的产物，服务端没有槽位能覆盖它，所以后台只能跟着它走。
    2026-11-23 曾把日号重置成「开服第 1 天」，结果后台显示第 4 天、客户端仍显示 99184，
    一天后回退；完整论证见 `docs/analysis-clock-axis-migration-2026-11-24.md`。
  - 天气模板的 `f0` 也是同一坐标系（`weatherPlanDay`，模板原值在 97235 这一档），
    因此 `weatherPlanDayOffset` 已归 0，面板日号直接就是模板日号，无需换算。
  - 这条同源关系由 `TestDayMatchesClientGameDay`（三个式子钉死）与
    `TestWeatherPreviewMatchesClientForecast`（逐图逐日比对）双重守住。
  - 曾经踩过的坑：`DayAndHour` 多加一个 `+1` 会让面板「今天」比客户端多一天，
    7 天预览窗口正好越界到客户端没下发的日号上，测试立刻报
    「面板第 N 天在客户端预报里不存在」。

## 参数导出与跨机同步

后台调出来的手感全在本地 SQLite 里（`data/rf4server.db`），不进 git。要在另一台机器复现同一套
玩法，用 `tools/config_sync.py` 打包搬运，不要直接拷库——主库里混着玩家存档、后台账号密码哈希
和网关登录令牌，整库搬过去等于把账号一起送人。

```bash
# 源机器导出（服务开着也能跑，只读快照）
python tools/config_sync.py export --out my-playstyle.json

# 看包里有什么（不连库）
python tools/config_sync.py show my-playstyle.json

# 目标机器：先预演，再导入
python tools/config_sync.py import my-playstyle.json --dry-run
python tools/config_sync.py import my-playstyle.json
```

包里是 **13 张表 / 约 750 行 / 550 KB**，覆盖后台所有可改项：`tunables`（89 条开关与数值）、
`fish_ecology_species`（253 条鱼种生态覆盖）、`fish_bait_override`（207 条饵料规则）、
`fish_bait_auto_rotation`、`fish_weight_preset` / `fish_weight_override`、`species_econ`、
`fish_bite_setting`、`fish_zone` / `fish_zone_fish`、`shop_item_override`，外加可选的
`craft_template`（`--no-player-scope` 可排除）。

**不导三类表**，理由都写进了包里的 `excluded_tables` 字段：

- **派生表**：`fish_ecology` 由 `ensureFishEcology` 从资产 JSON 按 `profile_version` 重灌，
  `hook_bite_profile` 由 `syncHookBiteProfiles` 从静态库 `item_def` 派生，`fish_grade_lines`
  由迁移灌入。导过去看似覆盖成功，服务下次启动又被重新派生，或行数对不上而静默半应用。
- **玩家存档**：`profile` / `item` / `rig` / `txn` / `mail` / `catch_log` 等。
- **会话态与凭据**：`gw_token`（网关登录令牌）、`gw_handoff`、`admin_user`（含 bcrypt 密码哈希）、
  `request_receipts`、`audit_log`、`kv`、`schema_migrations`。

导入的行为约定：

- 按**业务主键 UPSERT**，不是清表重灌——目标机自己加过、包里没有的行会保留。
- `fish_zone.id` 是自增主键、`fish_zone_fish.zone_id` 引用它，导入时**原样保留 id**，
  否则区域与鱼种的关联会整体错位。
- **单事务，全成或全败**。导入后逐表核对新增行数，与预演不符就整体回滚。
- 目标库缺列（比如还在 00083 之前，`fish_bait_override` 用 `fish_zh` 主键）会**直接拒绝**，
  列出缺哪些列，不写任何数据。目标库版本更高则只警告（多出的列保持现值）。
- 成功后在 `audit_log` 记一条 `import_playstyle`，带包 digest 与每表增减数。

生效时间与后台保存一致：多数参数 30 秒内生效，涉及静态资产的改动需重启主服。
验证过的口径：把源库参数清空后导入，13 张表**逐字段一致**；篡改几个值再导入能还原；
旧结构库被正确拒绝且未写入。

阶段奖励选择器先调用 `/api/catalog/groups?complete_only=1` 读取商品分类，再调用 `/api/catalog/items?complete_only=1&group=<key>` 读取当前分类。商品来自完整静态目录，因此活动专属商品即使没有 `shop_item` 货架记录也可以选择；竿坯、手柄、线轴和渔轮内部零件会被排除。普通目录调用不受这些筛选参数影响。

新年与周年活动均关闭时，阶段奖励编辑器处于禁用状态。开启任一活动后，奖励编辑器只显示已保存的活动分支；分支列表为空时不能编辑。移除分支会保留其已有奖励，重新加入后可以继续维护；“清空可选分支奖励”只清除当前可选分支的奖励。

活动分支 14、18 有 10 个阶段，其余活动分支有 7 个阶段；保存奖励时校验阶段是否存在和物品 ID 是否对应静态目录中的完整商品。数量表示实际件数：可堆叠物品合并，非堆叠装备逐件入包。游戏预览只显示物品种类，不表达数量；同物品多行配置的数量合计发放。关闭全部活动或从活动分支列表移除某分支后，该分支停止发奖，重新开启时可补发尚未领取的已完成阶段。
