# 鱼种适温方案落地报告（2026-11-23）

接 `analysis-fish-temp-calibration-2026-11-23.md`。那份报告解决了「温度怎么起作用」，
这一份记录**最终采用的方案、实施结果、以及过程中被推翻的两个判断**。

---

## 1. 最终方案（用户拍板）

设计目标由用户重新定义为：

> 增加各地图鱼种开口的随机性，使同一张图在不同温度区间能钓获不同鱼种。
> 稀有 / 超稀有窗口收窄，让它们更难钓；其它鱼按地图温度动态调整，
> **只要保证每个区间都有鱼钓，重叠了也没关系。**

落地规则：

| 稀有度 | 窗口半宽 | 总宽 | tolerance | 说明 |
|---|---|---|---|---|
| 普通 r0 | ±5.5℃ | 11℃ | 5.5 | 落在区分力甜点区 |
| 稀有 r1 | ±3.5℃ | 7℃ | 3.5 | 比普通难一档 |
| 超稀有 r2 | ±2.5℃ | 5℃ | 2.5 | 刚好高于 `max(2.2, ...)` 下限 |

超稀有不能更窄：`tolerance = max(2.2, 总宽/2)`（`fishing_weather_fishing.go:15`），
半宽压到 2.2 以下会被这条下限吃掉，收窄失效。

同亲本变种（锦鲤族、镜鲤族、草鱼白化等）在锚点 ±4℃ 内错位，
避免「13 条锦鲤全卡在 15℃、一次全中」。

## 2. 被推翻的两个判断（重要）

### 2.1 「地图温度够不够」要看全水层，不是中层

早期的判定一直用 `layer=0.45`（中层）算水温，据此得出「11 张图水温不够、暖水鱼无处安放」。

实测发现判鱼侧的水层是随钓法变的（`fish_bite_environment.go:541-552`）：

```go
layer := .45
switch {
case bottomRigTypes[c.rigType]:        layer = .93   // 底钓
case rigTypeLureFamily[c.rigType]:     layer = effectiveLureLayer(c)  // 拟饵泳层
case c.depthCM > 0:                    layer = normalizeWaterLayer(float64(c.depthCM) / 500)
}
```

按全水层（0 / .2 / .45 / .7 / .93）重算，**水温范围比只算中层宽 2.0~7.6℃**：

| 地图 | 仅中层 .45 | 全水层 | 扩宽 |
|---|---|---|---|
| 阿赫图巴河 | 6.0~25.8℃ | 4.9~32.2℃ | +7.6℃ |
| 北顿涅茨河 | 5.0~21.8℃ | 4.4~26.0℃ | +4.8℃ |
| 琥珀湖 | 3.7~19.8℃ | 3.6~22.9℃ | +3.3℃ |
| 挪威海 | 2.4~15.7℃ | 1.6~16.7℃ | +1.8℃ |

结论修正：**大部分图的温度本来够用**，之前的「不够」是测量口径错了。

### 2.2 全库水温下限是 1.55℃，不是 −3℃

原先把窗口下限写死 `LO_LIMIT = -3.0`。实测全库 69120 个逐时水温样本：

| 分位 | 水温 |
|---|---|
| 最低 | 1.55℃ |
| 0.1% | 2.29℃ |
| 1% | 3.47℃ |
| 5% | 4.73℃ |

≤2℃ 只占 0.029%，≤0℃ 为 0%。所以 −3℃ 以下是**永不触发的死区间**，
多出的 4.5℃ 还会挤占上限、并被误判成「偏离文献」。改到 `LO_LIMIT = 1.0`。

## 3. 地图气温修正（7 张图）

按全水层口径复核后，仍有 7 张图的**水温上限**覆盖不到名册鱼种的文献适温上限
（这些图名册几乎全是暖水鱼，如埃尔克湖 19 种全是 18℃ 以上的鲈鱼）。
用户选择「抬高地图水温」而不是压低鱼种适温。

工具：`tools/fish_temp_mapheat.py`（二分搜索抬升值，只改 `map_defs.json` 的日高温，
`rangeC` 日温差保持不变）。

| 地图 | map_id | 日高温抬升 | 抬后水温上限 |
|---|---|---|---|
| 埃尔克湖 | `level_019_american_pond` | +7.10℃ | 24.0℃ |
| 旧奥斯特罗格湖 | `level_004_torfyanoe_ozero` | +4.51℃ | 23.0℃ |
| 琥珀湖 | `level_014_carp_lake` | +4.07℃ | 25.0℃ |
| 苏拉河 | `level_008_sura_river` | +3.13℃ | 24.0℃ |
| 梅德韦杰湖 | `level_007_grass_lake` | +2.97℃ | 26.0℃ |
| 克马羚诺也湖 | `level_001_lake` | +1.83℃ | 23.0℃ |
| 铜湖 | `level_018_moskitnoe` | +1.45℃ | 25.0℃ |

气温→水温的传导比约 **1 : 0.34**（抬 15℃ 日高温只换来 5.1℃ 水温），
因为中间有两道压缩（`thermalResponse` 0.44~0.60，以及 `deep` 的 .22 系数）。
所以「要抬水温 1℃ 就得抬 3℃ 气温」，改动量比直觉大，必须算准再改。

## 4. 实施结果

### 4.1 覆盖率

按每图逐时水温统计，1℃ 一档检查「该档有几条鱼能钓」：

| 指标 | 结果 |
|---|---|
| 主温区 1℃ 档位达标 | **全部达标** |
| 主温区 2℃ 粗档达标 | **125 / 125（100%）** |
| 主温区定义 | 按频率累计取前 65~90%（鱼多的图铺得宽） |

### 4.2 稀有度难度

全库随机取温 2000 次，平均可钓条数：

| 稀有度 | 平均可钓 | 难度比 |
|---|---|---|
| 普通 | 67.7 条 | 1.00 |
| 稀有 | 10.9 条 | 0.16 |
| 超稀有 | 7.1 条 | 0.11 |

### 4.3 窗口宽度分层（验证未被破坏）

| 稀有度 | 条数 | 中位宽度 | 超出设计宽度 |
|---|---|---|---|
| r0 普通 | 169 | 11.0℃ | 部分（补缺时临时拉伸） |
| r1 稀有 | 45 | 7.0℃ | 0 |
| r2 超稀有 | 39 | 5.0℃ | 0 |

稀有与超稀有的窗口严格小于普通，分层未被补缺逻辑破坏。

### 4.4 与文献的偏离

253 条中 243 条落在文献区间内或仅微调；**10 条偏离 >0.5℃，合计 45.0℃**。
这些全部是「该图冷端没有冷水鱼」时被拉过去顶档的暖水鱼，例如：

| 鱼 | 文献 | 实际 | 所属代表图 | 原因 |
|---|---|---|---|---|
| `c.carp` 金鲫 | 8~31℃ | 1.0~12.0℃ | 沃尔霍夫河等 7 图 | 该图冷端无鱼 |
| `s_bass` 条纹狼鲈 | 8~27℃ | 1.0~12.0℃ | 埃尔克湖 | 19 种全是暖水鲈 |
| `walleye` 玻璃梭鲈 | 8~26℃ | 1.0~12.0℃ | 埃尔克湖 | 同上 |

这是「每档都有鱼」与「不曲解鱼种」之间的**结构性取舍**，
再想降只能改名册（给这些图加冷水鱼）或继续抬水温。

## 6. 关键工程坑（下次别再踩）

**导入必须带上其余习性列。**
`ReplaceFishEcologySpeciesCurated` 的 `INSERT ... ON CONFLICT DO UPDATE SET` 是**整行覆盖**，
指针为 `nil` 的列会被写成 `NULL`。只传温度三列会把昼伏曲线、饵料权重、
动作权重、底质、水色全部清空（`mergeFishEcologySpecies` 遇到 nil 会回退资产基线，
表面上不报错，实际覆盖全部失效）。

`cmd/fishtemp` 的做法是从 `fish_ecology` 把其余 18 列原样读出来一起写，
导入后校验「习性别非空率」必须与 `fish_ecology` 完全一致（当前 9 个习性列均 253/253）。

**窗口端点取整方向要一致。**
下限向下取整、上限向上取整（`_lo` / `_hi`），否则相邻两条鱼的窗口会在 0.1℃ 量级裂开缝隙，
出现「某个 1℃ 档 0 条鱼」的假缺口。

**WAL 模式下备份要用 `sqlite3.backup`。**
直接 `cp data/rf4server.db` 拿到的是不一致快照（`-wal` 里有未落盘数据）。

## 7. 复现方式

```bash
cd G:/Localfish/rf4_server_simulator

# 1. 生成方案（只读，输出 ref/fish_temp_final.csv）
python tools/fish_temp_dynamic.py

# 2. 报告需抬温的地图（--apply 才写 map_defs.json）
python tools/fish_temp_mapheat.py

# 3. 校验 CSV 与库 key 是否一致（不写库）
go run ./cmd/fishtemp -db data/rf4server.db -csv ref/fish_temp_final.csv

# 4. 真正导入（-apply）
go run ./cmd/fishtemp -db data/rf4server.db -csv ref/fish_temp_final.csv -apply
```

导入前记得先停 `launcher.exe` → `gameserver.exe` → `gateway.exe`，
否则 `bin/*.exe` 被占用会让后续构建写不进去。
