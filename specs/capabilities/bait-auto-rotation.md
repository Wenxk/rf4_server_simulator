# 鱼饵自动轮换

> 用法：改 `bait_rotation_*`、稀有度配额、抽样算法时对照本页。
> 饵料三档打分见 `bite-bait-and-spawn.md`；参数默认值与区间见 `docs/parameter-dictionary.md` 3.4。

## 1. 要解决的问题

鱼种「爱吃饵」名单常常覆盖几十上百款饵，等于没有偏好：玩家找到一款万能饵就能通吃，
不再探索。自动轮换把「名单内全部满分」收窄成「本期只有少数几款是正口」，其余归零。

## 2. 口径

- **配额由稀有度决定**：`fish_ecology.rarity_tier` → `0` 普通 3 款 / `1` 稀有 2 款 / `2` 超稀有 1 款
  （`autoQuota`）。稀有度是鱼种固有属性，不随水域变化。
- **抽样单位是「型号 × 形态」组**：先把 `allow` 展开成实际饵，再按
  （基础名去尾部规格编号 + 品类 + 饵型/拟饵型）聚组，组内按 `item_id` 排序。
  抽中一组 → 该组全部规格/颜色写入 `allow`；`deny` 命中的饵不进池。
- **形态不合并**：红虫活饵(`baitType=2`)、沉底煮饵(`1`)、Pop-up(`8`)、颗粒(`9`)、
  玉米(`10`) 分属不同组，跨形态的同口味也不合并（客户端数据里没有跨 3 形态的产品线）。
  同一基础名出现多个形态时，label 追加形态词（「红虫（10/14）· Pop-up」）。
- **抽样确定性**：种子 = `hash(fish_key, floor(now/周期))`，用 `rand.Perm` 取前 quota 组。
  同一周期内所有玩家、所有水域看到同一批开口型号；服务重启不丢状态；结果不写库。
- **实现方式：替换 allow，不改判鱼主循环**。抽样结果写进该鱼本期的 `allow`，后面完全走原路：
  命中 allow = 满分档（1.0~1.5）；没抽中的直接不在 allow 内（权重 0）。
- **组数不足不轮换**：`len(groups) <= quota` 时整条鱼退回「名单内全部满分」，避免把仅有的几种型号也关掉。
- **整类词就是池子**：`allow` 里写 `颗粒` / `浮水饵` / `拟饵` 这类大类词时，展开后这一类全部型号组
  都是候选池，本期开口饵按配额在**类内**抽；`deny` 写大类词则整类被排除。
  词表在 `internal/gameserver/bait_type_terms.go`（与后台「按大类加入」按钮同一份），
  匹配走 `BaitTypeTerm.matches`，不再散落在 `matchOne` 的分支里。
- **后台与判鱼同源**：`ExportedAutoRotation` 与运行时共用 `buildBaitGroups` + `autoPickGroups`；
  后台一次请求只加载一次全量饵定义（`RuleBaitList`），否则每条鱼会各查一遍 item_def。
  同一份结果放在 `/api/fish/config` 的 `bait_pick` 里，钓场页「爱吃的饵」列直接显示本期开口饵
  （配额 / 池子 / 抽中的型号 / 下次切换 / 总开关是否生效）；抽签参数（周期、轮次偏移、
  启用的覆盖）与判鱼读同一份，刷新即最新。
- **参与资格是独立开关**：表 `fish_bait_auto_rotation`（主键 `fish_key`，只存开启项）。
  **不写进 `fish_bait_override.rotate_mode`**——覆盖表整行替换内置规则，把开关塞进覆盖行意味着
  给没有覆盖的鱼开开关就得先复制内置 252 条规则，从此跟不上内置表更新。
- **两层开关**：全局 `bait_rotation_auto_enabled` + 逐鱼开关，两个都满足才轮换。
- **唯一动态 allow 来源**：手工轮换组（`groups_json` / `rotate_sec` / `rotate_mode`）已删除；
  自动抽取直接把本期抽中的型号写进 `allow`，其余饵按严格 allow 归零。

## 3. 边界

- 只放行「本期抽中」的饵；名单外直接 0，不再走 companion 或同食性保底。
- 没有 `allow` 规则的鱼不参与自动抽取，仍按 companion 证据兜底。
- 前置条件（海图区号、jig 阶梯、顺水漂流、上船）照旧先判，不满足直接不出候选，与轮换无关。
- 池子按**规则指纹**缓存（allow+deny+bottom 的哈希），规则或名单一变即失效重建。
  单款饵的名字派生字段（`ruleName` / `ruleKey` / 型号基础名）另有进程内缓存
  `baitDerivedCache`（键是 `item_id + 原始名`，改名会自动重算）：构建一个池子从 ~10ms
  降到 ~1ms，后台一次算几十条鱼才不至于把页面拖慢。缓存只影响速度，不影响抽签结果。
- 时间桶全局对齐：所有鱼在同一时刻切换。周期改动后下一次切换按新长度重新对齐，不保证连续。

## 4. 提交前快速自检

- [ ] 关掉 `bait_rotation_auto_enabled` 后，输出与轮换前逐位一致（名单内全部满分）。
- [ ] 同一时间桶内两次判鱼抽到同一批饵；跨桶后至少有一次不同。
- [ ] 稀有度 0/1/2 分别只开 3/2/1 个型号；组数不足时全部放行。
- [ ] 抽中「红蚯蚓（10/14/18）」时三个尺寸都在 allow 里；活红虫与红虫味 Pop-up 不同组。
- [ ] 打开逐鱼开关不会在 `fish_bait_override` 里生成新行（开关与规则覆盖解耦）。
- [ ] 未抽中的饵权重为 0；只有没有 allow 规则的鱼才按 companion 证据兜底。
- [ ] 名单外的饵不再被轮换改动——有 allow 时它们本来就不在准入范围。
