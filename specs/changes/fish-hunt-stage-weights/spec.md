# 鱼猎四阶段权重改为后台可调

Status: in-progress

## Problem Statement

发鱼模式选中「鱼猎四阶段」时，四个阶段（日常 / 聚鱼 / 发窝 / 巨物发窝）的四档占比
（未达标 / 达标 / 奖杯 / 蓝冠）是 `fishHuntWeights` 里的字面量：

| 阶段 | 未达标 | 达标 | 奖杯 | 蓝冠 |
|---|---:|---:|---:|---:|
| 日常 | 74.7 | 24 | 1 | 0.3 |
| 聚鱼 | 54.5 | 43 | 2 | 0.5 |
| 发窝 | 30 | 61.2 | 6.8 | 2 |
| 巨物 | 10 | 64 | 20 | 6 |

同目录下的「档位比例」和「两档制」两组表都能在后台调，只有四阶段这 16 个数字要改代码
重编译。管理员调「日常阶段别那么小鱼」「巨物阶段奖杯再高一点」必须走开发流程，
与另外两种模式的操作体验不一致。

## Solution

把 16 个百分比改成 16 个 tunable，默认值等于当前字面量，行为零变化：

```
hunt_stage_daily_{below,qualified,trophy,super}    74.7 / 24   / 1   / 0.3
hunt_stage_gather_{...}                            54.5 / 43   / 2   / 0.5
hunt_stage_active_{...}                            30   / 61.2 / 6.8 / 2
hunt_stage_giant_{...}                             10   / 64   / 20  / 6
```

后台「游戏参数 → 发鱼模式」在选中鱼猎四阶段时显示一张 4×4 表格，逐格输入相对权重，
实时显示归一后的占比；保存时按组归一到总和 100%（与两档制同口径）。

## Implementation Decisions

- 读取口径 `fourStageGradeWeights(stage)`：逐键读 tunable，负值 / NaN / Inf 按 0，
  四档全 0 回退该阶段默认表，否则归一到总和 100。与 `twoStageGradeWeights` 完全同构。
- 生效范围与现在一致：淡水、海钓、路亚三条分支都走同一张阶段表；两档制开启时淡水仍走
  两档表，海钓路亚仍走这张四阶段表（`fishHuntWeights` 的 else 分支）。
- 归一之后再叠加的倍率不动：奖杯保底（pity≥30 ×1.5、≥50 ×2）、奖杯幸运（上限 +50%）、
  脱钩回访（奖杯 ×1.3、蓝冠 ×1.5）、`forceTrophy` 归零前两档。它们作用在归一后的
  相对权重上，因此调表不会改变保底的触发条件。
- 后台校验：`hunt_stage_` 前缀的写入必须是有限非负数，与 `two_stage_` 同一段逻辑。
- 不改表结构、不改协议、不改 `RolledFish` 快照字段；阶段名与日志不变。
- 回滚：删掉这 16 个 tunable 行即回到默认表，无需回滚代码。

## User Stories

1. 作为管理员，我希望在鱼猎四阶段模式下直接改四张表的 16 个百分比，最多 30 秒生效。
2. 作为管理员，我希望输入的是相对权重而不是必须凑满 100 的百分比，保存时自动归一。
3. 作为管理员，我希望看到每一行归一后的实际占比，避免「填了 20 却以为是 20%」。
4. 边界：四档全填 0 时不接受保存；服务端遇到全 0 时回退默认表，不会出现「该阶段不出鱼」。
5. 边界：两档制与档位比例两种模式不受影响；鱼猎四阶段受 `grade_ratio_enabled=1` 压制时
   这张表整体不参与（与改动前一致）。

## Testing Decisions

- 单元层：`fishHuntWeights` 直调——默认值四档逐字面量（现有 `TestFishHuntStageWeights`
  继续通过）、自定义值归一到 100、全 0 回退默认、负值按 0。
- API 层：`hunt_stage_` 前缀写入负数被拒；合法数字写入成功。
- 界面层：后台鱼口页切到鱼猎四阶段后出现 4×4 表格；改一格时该行占比即时变化。
- 期望值来源：spec 里的默认表与自定义样例，不用同一份代码反推。
