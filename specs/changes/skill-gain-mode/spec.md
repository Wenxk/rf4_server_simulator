# 技能升级概率三档模式

Status: done

## Problem Statement

技能熟练度原先只按随当前熟练度衰减的原版概率增长。后台缺少整体切换能力，无法快速恢复原版、统一测试必涨路径，或在多个技能之间逐项调参；逐个写库还可能留下部分更新状态。

## Solution

新增八类技能的固定概率参数 `skill_gain_pct_*`（本地另补 `skill_gain_pct_7` = 配置饵料 / 混合诱饵，上游清单漏了这一档，不补则「一键百分百」时该技能仍走原版公式）：

- `0` 保持原版概率公式；
- `1..100` 直接按该百分比判定是否增长，`100` 必定增长；
- 固定模式不叠加欢乐时光对原版概率的修正；
- 捕获鱼饵的挖饵和制作、烹饪、混合诱饵、制作拟饵均按既定技能大类生效。

本地单页后台在「收益与通知 → 技能成长」提供“原版概率 / 全部 100% / 自定义”三档切换（上游拆成模块化 SPA 后同一功能在「数值调整 → 经验与奖励」）。原版与百分百通过单次管理 API 原子更新八个概率和界面模式标记；自定义仅切换模式并逐项保存。

## User Stories

1. 管理员可以一键恢复全部技能为原版增长概率。
2. 管理员可以一键把八类技能设为 100% 必定增长。
3. 管理员可以逐个技能设置 0–100 的固定概率，并保留其他技能当前值。
4. 固定概率在钓获结算、挖饵和制作链路中使用同一套判定，不受欢乐时光概率修正干扰。

## Implementation Decisions

- 概率参数保存在 `tunables`，按技能大类读取并沿用 30 秒缓存。
- `skill_gain_mode` 只作为后台 UI 持久化标记；后端以八个概率值决定行为。
- `POST /api/skill_gain_mode` 原子写入批量模式：`native`、`fixed100`、`custom`。
- 固定模式仅替换“是否增长”的概率，命中后 0.1/0.2 的增量规则保持不变。
- 制作类技能按每个制作件独立判定；挖饵按每次挖饵独立判定。
- 本地只有一个单页后台，本轮控制直接加在该页「收益与通知」页签内。

## Testing Decisions

- 概率纯函数覆盖 0=原版、50=按阈值、100=必定命中、未配置回退原版。
- 钓获结算覆盖固定 100% 写入熟练度，并覆盖固定模式不叠加欢乐时光修正。
- 制作链路覆盖多件独立判定；挖饵覆盖固定概率命中判定。
- 管理 API 覆盖三种模式、自定义值保留、非法模式和原子批量写入。
- active SPA 测试覆盖三档按钮、切换到自定义后显示八个输入框。
- 完成门禁：`go test ./...`、`go vet ./...`、`go build ./...`、doccheck、JS 语法检查。

## Out of Scope

- 不改变技能满级上限、技能书目标值或技能点分配规则。
- 不调整技能大类与配方的映射关系。
- 不把 legacy 单页作为长期维护目标。
