## Problem Statement

用户提出的口径：**同克重下，稀有鱼与超稀有鱼的单价不应低于普通鱼**。

审计方法：对每个稀有 / 超稀有鱼种，取「蓝冠线索引在 0.5~2 倍」的普通鱼作为同量级参照，
算出这些普通鱼单价的 p90。若该稀有鱼单价低于这条线，就是稀有度没有在价格上体现。

## User Stories

1. 作为玩家，我希望标着「稀有」的鱼在同重量下比普通鱼值钱，否则稀有度标签没有意义。
2. 作为运营，我希望鲤鱼家族的价格成层级：普通（1.4–3.3）< 稀有（9.2–10.0）< 超稀有变体（13.3+）。
3. 边界：本次只把「低于普通鱼 p90」的鱼提上来，已经高于 p90 的 59 种稀有鱼一律不动。

## Implementation Decisions

- 只改 `internal/gameserver/assets/fish_market_prices.json` 的 20 个基准价，
  `revisions` 追加一条记录指向本 spec。
- 判定式：`稀有鱼单价 >= 同量级（蓝冠线 0.5~2×）普通鱼单价的 p90`；
  同量级普通鱼少于 2 种时跳过（分位数在 n<2 时不可信）。
- 平滑规则：同一下界组内按原价升序，映射到 `[p90, p90×1.45]` 的等差序列。
- **不抬高普通鱼的「元凶」**：`wfish`、`molva`、`nelma`、`m_zubatka` 这几种普通鱼
  在同量级里溢价 1.8~2.8 倍，是「击败稀有鱼」次数最多的（前 5 种占 80/174 次）。
  但它们是正常的洄游/海产鱼，压价会误伤经济；改为对齐稀有鱼一侧更稳。
- 不动四档阶梯、不动饵料鱼（18 种）、不动巨型鱼（9 种）。

## Testing Decisions

- 新增 `TestRarityPriceNotBelowCommon`：锁定 20 个鱼种中代表性的一批，断言其单价不低于
  同克重普通鱼 p90。已验证**有效性**：把 `n_carp` 改回 2.62 会立即报错
  （`n_carp(r=1) 单价 2.62 低于同克重普通鱼 p90 2.80`），恢复后通过。
- `TestSpeciesDefaultsConsistent`（四档单调）、`TestNoPriceOutlierBySizeClass`（溢价不超过 p90×5）
  继续覆盖，改价后均通过。
- `TestSpeciesDefaultsCorrected` 的锁定表未包含这 20 种，无需同步（它锁的是历史校正项）。

## Out of Scope

- 不改稀有度本身（`species_rarity` 来自静态库，属鱼种固有属性）。
- 不改经验的稀有度表现——经验侧已是统一阶梯，鱼种差异只体现在未达标基数。
- 不处理「同稀有度内部的价格离散」（如超稀有里 `hi_utsri` 17.53 与 `carp_albino` 10.30 并存），
  那是鱼种个体差异，不是稀有度错配。
- 不调整 4 种「元凶」普通鱼（`wfish`/`molva`/`nelma`/`m_zubatka`）的溢价。

## Further Notes

- [事实] 审计前的比值分布（相对同克重普通鱼中位）：普通 中位 1.00（p10 0.42 / p90 2.39）、
  稀有 中位 3.06（p10 1.62 / p90 6.36）、超稀有 中位 3.81（p10 2.29 / p90 12.33）。
  **整体是有稀有度溢价的**，问题只出在低尾的 20 种。
- [事实] 20 种里有 16 种属于鲤鱼/锦鲤家族——这不是巧合：鲤鱼家族的普通种定价偏低
  （`carp` 1.76、`m_carp` 1.40、`g_carp` 1.90），而它们的变体（`_ghost`/`_albino`/`_red`/
  锦鲤系列）作为稀缺皮肤按「略高于本体」定价，结果被同家族外的普通鱼（`s_carp` 3.33、
  `l_carp` 2.80）反超。
- [推断] 若后续把稀有度接入「经验/价格双通道」，应把本 spec 的判定式写进自动审计，
  而不是靠人工比对。
- [假设] 稀有鱼提价不会显著影响服务器经济：这 20 种里 16 种是鲤鱼变体，产出率本就很低
  （`species_grade` 里多数 trophies 计数为个位数）。
## 补漏（同轮追加，2026-11-23 晚）

首轮把 20 种「提到 p90」后，全量 253 种复验发现两类残留缺陷：

### 1. 提价目标直接等于 p90，等于零溢价

首轮把 `n_carp`/`sh_barbel`/`syb_sterlet` 的单价**设成与 p90 相同的数值**（9.20/14.61/20.45），
而这三个 p90 恰好分别来自某条普通鱼（`nelma` 9.20、`mikija` 14.61、`katran` 20.45）——
也就是说稀有鱼与普通鱼**价格完全相同**，稀有度一点没兑现。这是「一律齐平 p90」的必然结果。

### 2. p90 自指：基线含被判定鱼自身，越提越追不上

复验时把 `eel` 从 24.36 提到 26.13（当时 p90 = 26.13），再跑审计发现 p90 也变成了 26.13，
于是又判定不合格；再提到 26.39，p90 再涨。根因是分母里混进了被提价的鱼，形成发散循环。

**修正**：判定时基线只取普通鱼，且显式排除被判定鱼本身（`ck != k`）。修正后 p90 稳定在
24.36 / 26.20，不再随提价漂移。

### 3. 齐平不算兑现：改为要求 1% 以上溢价

判定式收紧为：

```
稀有鱼单价 >= 同量级（蓝冠线 0.5~2×）普通鱼单价 p90 × 1.01
```

### 新增可复现审计工具

`tools/fish_price_audit.py`：读实机库（`data/rf4server.db` 提供 `species_rarity` 与
`fish_grade_lines`）+ 内置价表，跑两条判据（离群 / 稀有倒挂），退出码 0/1/2。
支持 `--include-bait`（把饵料鱼纳入基线）与 `--report`（打印各体型档 p90 与饵料鱼清单）。

**饵料鱼的判定修正**：早期误按 `loc_bait_fish.fish_key` 判「这种鱼是饵料」，但那列其实是
「该地点该饵料能钓到哪些鱼」的钓获统计，250 种鱼全在里面。正确判定是看 `loc_bait_fish.bait`
里的**饵名**是否包含该鱼中文名（炮制出 26 种，含 `halibut_w`，不是早先手写的 18 种）。

**未采用的更严口径**：若把下界改成「对齐同量级最强的单条普通鱼」，会要求改 25 种，
但其中多数是被 16 种自身已超 p90 的普通鱼（`sebastes_n` 1.40×、`kw_tench` 1.40×、
`golets_lev` 1.27×、`c_squid` 1.24×、`m_zubatka` 1.23×、`wfish` 1.14×）拉高的。
压低这些普通鱼会误伤既有经济，故维持 p90 口径。
