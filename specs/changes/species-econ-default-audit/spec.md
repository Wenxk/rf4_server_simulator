# 鱼种经济默认值一致性校正

Status: done

## Problem Statement

「鱼种经济」页把 253 个鱼种的默认经验与默认鱼价摊开之后，暴露出三类自相矛盾的数值：

1. **鱼价档位倒挂 9 种**：上星价（g3）低于达标价（g1），例如东西伯利亚茴鱼 28.04 → 16.83、
   河螯虾 84.27 → 51.25。玩家把鱼养成上星反而每公斤更便宜。
2. **缺价 2 种**：拟鲤（`roach`）与巴尔喀什鲑（`bs_salmon`）在价表里没有任何档位，
   卖鱼时落到基础速率兜底（约 3.57 银/公斤），6 kg 的拟鲤只值 21 银。
3. **经验档位非单调 22 种**：这些鱼种零实测、数值全来自亲缘组锚，而组锚本身按档取实测中位，
   不同档的样本来源不同，出现 g4 < g3（marine_rock / roach_run）、g3 < g2（herb_carp）
   甚至 g1 ≫ g2（weak_silver 里的青蛙，被牡蛎 179.9 XP/克拉高）。另有 3 个鱼种完全没有
   任何映射，四档都是 0.4 兜底。

## Solution

按「同一鱼种内档位越高、单位收益不得下降」的一致性规则校正默认值，只改自相矛盾的行，
不做整体重估。校正后 253 个鱼种四档经验单调不减、四档鱼价齐全且不倒挂；新增一条测试
把这些约束锁住，防止以后又混进倒挂数据。

## User Stories

1. 作为玩家，上星/蓝冠鱼每公斤不应比达标鱼更便宜；高一级的鱼给的经验不应更少。
2. 作为运维，打开「鱼种经济」页时每个鱼种都有四档价格可对比，不再出现「价表缺失」。
3. 边界：没有实测样本的鱼种仍按亲缘组推断，但推断结果必须单调；改完不影响任何一条
   官服实测锚点（213 条断言保持绿）。

## Implementation Decisions

- **鱼价倒挂**：`g3 = g1`（对齐到「无上星溢价」这一在价表中已存在 59 例的形态），
  `g4 = max(原 g4, 1.5 × g3)`（保留该行自身的 1.5 倍蓝冠比例，不强行拉到 2 倍）。
  涉及 `os_grayling`、`chir`、`sebastes_m`、`v_bream`、`sig_vouksa`、`crawfish`、
  `sig_valaam`、`salvel_l`、`riv_brown_trout`。
- **缺价补齐**：`roach` 与 `c.roach`（常见拟鲤）同属同体型段，直接沿用其四档价；
  `bs_salmon` 与 `l_salmon`（拉多加鲑）同科且达标/蓝冠线完全一致（14 kg / 20 kg），沿用其四档。
- **组锚单调化**：`marine_rock` g4 69.4414 → 99.9988、`roach_run` g4 5.0012 → 13.8887、
  `herb_carp` g3 5.5466 → 5.7485。当时的约定是「g4 无观测沿用 g3」，后续已改为 2×g3。
- **无实测种推断表**：新增 `fishXPInferred`，只放 4 种：`roach` 沿用 `c.roach` 四档；
  `s_lamprey` / `trid_lamprey` 沿用 marine_rock 修正后的四档（与 `c_lamprey` 同科同组量级）；
  `frog` 改用 `small_forage` 组量级。该表优先级在别名之后、亲缘组之前，注释标明「勿当实测」。
- 数据只改 `fish_xp_rate_table.go` 与 `fish_market_prices.json`，不动表结构、协议与后台接口。

## Testing Decisions

- `species_defaults_test.go`：
  - `TestSpeciesDefaultsConsistent`：遍历静态库 253 个鱼种，断言四档经验 >0 且单调不减、
    四档鱼价 >0、g1==g2、g3>=g1、g4>=g3。回滚任一修正都会变红。
  - `TestSpeciesDefaultsCorrected`：锁定 11 个鱼种的四档价格与 8 条手算经验值
    （如 `roach` g2 300g = trunc(0.3007×300) = 90），防止被后续改动改回去。
- 原 `TestOfficialXPAnchors`（213 条官服实测）保持原样并通过，证明没有动实测值。

## Out of Scope

- 不重估 g3/g1 溢价比例：价表中 4.0（68 种）、1.0（59 种）、2.0（20 种）、3.0（19 种）并存，
  属真实鱼种差异，无官服依据时不做统一。
- 不改「g4 与 g3 同乘子」的模型限制——这一条已由 `specs/changes/xp-g4-above-g3` 处理，
  并最终由 `specs/changes/unified-grade-ladder` **定稿**：g4 = 2×g3，
  四档经验 1 : 3.265 : 20.40 : 40.81、鱼价 1 : 1.5 : 3 : 6 为游戏内结算基准，不再补实测。
- 不处理亲缘组 `carp_mid` 与 `weak_silver`（g1=179.9）的非单调组值：两组没有
  零实测成员，当前不影响任何鱼种；改动会覆盖实测中位。统一阶梯上线后组表只保留
  g1 基数，这两项仅作 g1 取值存在，不影响档位形状。
- 不补 `roach` / `s_lamprey` / `trid_lamprey` 的中文名（`loc_fish` 缺行，属静态库名册问题）。
- 不调整 `carp_mid` 等极端值（`ostrea_ed` g3 3671 XP/克）——这是 g1 锚 × 档位乘子的模型结果，
  与官服 g1 实测一致，非本次数据错误。

## Further Notes

- [事实] 价表 251 行全部 `g1 == g2`，`g4/g3` 为 2.0 的 193 行、1.5 的 43 行，倒挂 9 行。
- [推断] 9 行倒挂的 g3 属样本噪声：其 g3/g1 落在 0.60–0.94，而同表另有 59 行 g3 恰等于 g1，
  对齐到 1.0 是改动最小且落在既有形态内的做法。
- [推断] `roach` 与 `c.roach` 同种异名，`bs_salmon` 与 `l_salmon` 同科同规格；沿用而非重估。
- [假设] `s_lamprey` / `trid_lamprey` 与 `c_lamprey` 同科，经验量级一致；无实测，仅保证不再落 0.4。
